# AURORA V1.4.3 — Shareable Case Dossiers

AURORA now has one responsive, accessible dossier template with **two independent kinds of evidence**:

- **Historical references:** `/archive/<case-id>` uses only `data/cases.json` (eight sourced V1.3 examples). These are not D1 records, never counted as registered sightings, and never confused with the fictional DEMO reports.
- **Reviewed D1 records:** `/cases/<case-id>` reads `/api/cases/<case-id>`, and the API still requires both an attached `DB` and `AURORA_REGISTRY_PUBLIC=enabled`. If D1 is off, visitors see a clear unavailable message. If the case is missing/unpublished/rejected, no dossier contents are shown. There is **no fallback** to the legacy archive for D1 case URLs.

All pages are served through one `dossier.html` template and dynamic Cloudflare Pages Functions. There is no one-HTML-file-per-case generation.

The dossier UI shows: date/date precision, region, observation category, exact publication/assessment distinction, location accuracy, original AURORA summary, original-source link, and where available the assessment authority and confidence. Approximate coordinates are labeled as map anchors, not measured object positions. The template does not download or expose attachments, identities, private contact data, R2 objects, or media lacking rights.

### Entry points

- Globe selected case -> **OPEN CASE DOSSIER**. Historical archive mode points to `/archive/...`; active D1 mode points to `/cases/...`.
- Country page expanded case card -> permanent reviewed D1 dossier.
- Source links open via HTTPS with `rel="noopener noreferrer"`. Case content is inserted using `textContent`, not HTML interpolation, to avoid script injection from source descriptions.

### Operational deployment

Dossier code is safe for V1.4's staged production: historical pages already work without D1. A D1 URL remains unavailable until the separately verified database is activated. No Cloudflare binding or secret is added by this PR.

### Tests

Run the existing suites:

    node --test tests/aurora-v1.test.mjs
    node --experimental-sqlite --test tests/database.test.mjs
    node --experimental-sqlite --test tests/aurora-browser.test.mjs

The new Chromium tests exercise an actual historical reference dossier in a 390px mobile viewport, a D1-backed case dossier using the real SQLite API adapter, a disabled D1 case, nonexistent archive record, and a globe-to-dossier link. They assert source URLs, uncertainty, publication interpretation, and absence of mobile overflow.

### Known next steps

For broader evidence packages, add a moderated **rights-verified R2 media service**, controlled upload handling, safe metadata stripping and a release review, rather than linking to unverified private files. Public submission remains disabled. See [V1.4.2 D1 rollout](V1.4.2-REGISTRY-RELEASE.md).
