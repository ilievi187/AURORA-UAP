# AURORA V1.7 — production activation of text-only reports

**Status: operator action required.** Merging this code does not activate public intake. Never set review flags or claim reports are accepted without the checks below. GitHub CI uses mock Turnstile and local SQLite; these are not production credentials.

## What we have
- The primary homepage and Join CTAs link directly to `/report.html`.
- When `GET /api/intake/status` says `accepting:true`, the form requires policy consent and a genuine Turnstile token. Its HTTPS POST to `/api/intake/submit` stores a report in a **private** D1 quarantine and returns HTTP 202 with a unique receipt.
- Public case data, public registry and historical demo are **separate**. No contact/email fields, media uploads or public auto-publication.
- The private intake no longer requires `AURORA_REGISTRY_PUBLIC=enabled`. That flag controls **only the public research registry**.

### Cloudflare dashboard protection checklist (not completed by a GitHub merge)

**Cloudflare Zero Trust → Access → Applications:** Configure a Self-hosted application for the moderator origin and explicit paths `aurorauap.org/moderation`, `aurorauap.org/moderation.html`, and `aurorauap.org/api/moderation/*` (separate applications if the UI requires it). Use an **Allow** policy for exactly the nominated moderator identity; disable bypass policies. Set `AURORA_ACCESS_TEAM`, `AURORA_ACCESS_AUD`, `AURORA_MODERATOR_EMAIL` and `AURORA_MODERATION_ENABLED` only after verifying Access's real application ID/audience and signed identity at the origin. A preview or missing credentials must return 403. The HTML is protected at origin by `functions/_middleware.js` as defense in depth, but this is **not** evidence that the Cloudflare Access application has been created.

**Security → Security rules → Rate limiting rules:** Create a rule named `AURORA — intake spam throttle` on the `aurorauap.org` zone. For free-tier-compatible matching, choose URI Path equals `/api/intake/submit`. If your plan supports it, additionally filter Hostname equals `aurorauap.org` and Request Method equals `POST`. Track by source IP; as an initial safe setting, use **5 requests per 60 seconds per IP**, action **Block**, mitigation **10 minutes**, then tune using observed legitimate/abuse traffic. This is a starting configuration, not a guarantee of strict per-IP limits or proof of deployment. Confirm actual saved rule, action and plan compatibility in the dashboard. See [Cloudflare's current rate-limiting guide](https://developers.cloudflare.com/waf/rate-limiting-rules/create-zone-dashboard/). Do **not** set `AURORA_INTAKE_WAF_REVIEWED=yes` until verified.

**Workers & Pages → aurora-uap → Settings → Runtime:** Select **Fail closed** rather than Fail open for Pages Functions if your plan exposes this option, because otherwise a Functions quota exhaustion may serve protected static pages without middleware. Confirm the Pages production deployment actually invokes middleware for the canonical moderator path and its `.html` alias, and `GET /api/moderation/` fails closed without Access.

**Protection smoke:** Using no credentials, verify GET `/moderation` gives 403 rather than HTML, and GET `/api/moderation/` gives 403. Only after configuring real Access and the moderator binding should a nominated moderator be able to read the private queue; a different identity must still be denied. Validate the actual WAF rate-limit rule with controlled synthetic requests and no personal data. Keep `AURORA_INTAKE_ENABLED` disabled until the real privacy notice, D1 migration, Turnstile secrets and moderator Access/WAF are all verified.

| `AURORA_TURNSTILE_SECRET` | Your **actual** secret (encrypted secret only) |
| `AURORA_MODERATION_ENABLED` | `enabled` only when reviewed moderator API and verified Access policy are deployed |

| `AURORA_ACCESS_AUD` | Actual 64-hex-character Access application audience |

## Production smoke test

1. Redeploy after changing Cloudflare bindings/variables. Visit `https://aurorauap.org/api/intake/status`; it must return JSON with `accepting:true` and `mode:"text_only_quarantine"`. If false, stop; do not announce live intake.
2. Open `https://aurorauap.org/report.html` on desktop and 390-px mobile. Complete consent and a **real** Turnstile challenge. Send a deliberately synthetic report with no personal details.
3. Verify HTTP 202, `status:"pending"`, `published:false` and `aur-int-...` receipt. Inspect private D1 `intake_submissions` and its `received` audit event. Verify the public cases table did **not** change.
4. Verify wrong Origin, expired challenge, spam field, invalid payload, disabled intake and duplicate request key all fail closed or remain idempotent. No personal reports should be used for testing.
