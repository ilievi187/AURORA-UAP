# AURORA V1.7 — production activation of text-only reports

**Status: operator action required.** Merging this code does not activate public intake. Never set review flags or claim reports are accepted without the checks below. GitHub CI uses mock Turnstile and local SQLite; these are not production credentials.

## What we have
- The primary homepage and Join CTAs link directly to `/report.html`.
- When `GET /api/intake/status` says `accepting:true`, the form requires policy consent and a genuine Turnstile token. Its HTTPS POST to `/api/intake/submit` stores a report in a **private** D1 quarantine and returns HTTP 202 with a unique receipt.
- Public case data, public registry and historical demo are **separate**. No contact/email fields, media uploads or public auto-publication.
- The private intake no longer requires `AURORA_REGISTRY_PUBLIC=enabled`. That flag controls **only the public research registry**.

## Critical production gates (must be independently verified)

1. **Real privacy notice.** Establish verified legal data-controller name, a privacy contact and rights request process, lawful basis, Cloudflare hosting/subprocessors, concrete retention/deletion policy, treatment of personal data in free-text reports, moderation and separately authorized publication. Have the policy reviewed as appropriate for Bulgaria/EU. Start from [unpublished drafting worksheet](PRIVACY-NOTICE-DRAFT.md), *not* a placeholder published at `/privacy`. Publish the actual reviewed notice at `https://aurorauap.org/privacy`.
2. **Cloudflare D1**. Identify the correct production database, verify backups, existing `0001_init.sql` and apply `migrations/0002_intake_quarantine.sql` through an authorized Wrangler/cloud account. Do not recreate an existing production D1. Bind this database as `DB` in Pages **production** Settings → Bindings. Confirm both `intake_submissions` and `intake_review_events` are present using read-only SQLite metadata query.
3. **Cloudflare Turnstile**. Create a production widget restricted to `aurorauap.org`. Configure the public site key as an environment variable, and secret key as an encrypted Cloudflare secret. Only the backend verifies tokens with Cloudflare Siteverify and checks hostname/action.
4. **WAF rate limits and monitoring**. Configure and test Cloudflare WAF/Rate Limiting for POST `/api/intake/submit` (for example an appropriate per-IP throttle and action). Consider URL normalization, bot traffic, incident alerts and account limits. [Cloudflare guidance](https://developers.cloudflare.com/waf/rate-limiting-rules/best-practices/). Do not claim WAF is reviewed merely because Turnstile is configured.
5. **Moderation / retention**. Define a person who reviews private submissions, a secure authenticated method to view them in D1, an audited human-only decision, procedures for user deletion/retention and backup/restore. No public administrative route is shipped here.

## Production environment variables

Under Cloudflare Pages project → Settings → Variables and Secrets (Production), and only after verifying prerequisites:

| Key | Required value |
| --- | --- |
| `AURORA_INTAKE_ENABLED` | `enabled` (**set last**) |
| `AURORA_INTAKE_LEGAL_APPROVED` | `yes` (only after real review) |
| `AURORA_INTAKE_WAF_REVIEWED` | `yes` (only after rule verification) |
| `AURORA_INTAKE_POLICY_VERSION` | `intake-v1-reviewed` |
| `AURORA_INTAKE_POLICY_URL` | `https://aurorauap.org/privacy` |
| `AURORA_INTAKE_HOSTNAME` | `aurorauap.org` |
| `AURORA_TURNSTILE_SITE_KEY` | Your **actual** site key |
| `AURORA_TURNSTILE_SECRET` | Your **actual** secret (encrypted secret only) |

`DB` is a D1 database binding, not a string. Neither account IDs nor secrets go to GitHub. `AURORA_REGISTRY_PUBLIC` need not be enabled for private reporting.

## Production smoke test

1. Redeploy after changing Cloudflare bindings/variables. Visit `https://aurorauap.org/api/intake/status`; it must return JSON with `accepting:true` and `mode:"text_only_quarantine"`. If false, stop; do not announce live intake.
2. Open `https://aurorauap.org/report.html` on desktop and 390-px mobile. Complete consent and a **real** Turnstile challenge. Send a deliberately synthetic report with no personal details.
3. Verify HTTP 202, `status:"pending"`, `published:false` and `aur-int-...` receipt. Inspect private D1 `intake_submissions` and its `received` audit event. Verify the public cases table did **not** change.
4. Verify wrong Origin, expired challenge, spam field, invalid payload, disabled intake and duplicate request key all fail closed or remain idempotent. No personal reports should be used for testing.
