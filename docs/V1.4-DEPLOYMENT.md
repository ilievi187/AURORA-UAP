# AURORA V1.4 — Database rollout

## Quality audit — country explorer and international fallback

The cloud preview was inspected via a connected read-only browser tab. It currently reports `D1 / NOT CONNECTED` correctly; live published-case counts must stay unavailable until real D1 binding and migration. The audit identified stale API responses when switching filters, partial-locale error messages left in Bulgarian, an invalid nested tag in a select option, and a prepopulated country choice that did not come from D1. These were corrected in this feature branch. Country-page requests now cancel superseded fetches and advance pagination only after a successful response; browser tests check deliberately delayed responses. The register and globe offline states use English fallback for partial locales, and stale case links are hidden when a filter returns nothing.

These UX and integrity fixes are **code changes in the PR**, not proof that the live Cloudflare database has been provisioned. The original production site remains on the last merged V1.3 commit until D1 deployment checks are complete.

**Deployment blocked: do not merge PR #6 until a real Cloudflare D1 is created, populated, bound to Pages and verified.**

## Actual code
- migrations/0001_init.sql creates cases, sources, case_sources, moderation_events, media_assets and import_runs.
- Pages Functions endpoints: /api/cases, /api/cases/:id, /api/stats, /api/countries/:code.
- Each returns real D1 results via prepared statements. Non-approved, unpublished and DEMO entries are excluded. If D1 is absent, HTTP 503; never fake counts.
- One country.html template serves /countries/DE and other ISO country routes with search, year/region/type/status filters, map, details and a local-draft-only CTA.
- The old rotating globe now requests the API; no static historical fallback. Legacy DEMO scenarios remain visually separate.
- Global Earth filters (country, year, case category, AARO source assessment) now issue **new D1 queries** rather than filtering just the first 250 records. Country and year filter choices are built from comprehensive D1 aggregation and include records beyond the initial page. Each filtered globe view still caps at 250 markers, with a clear first-250 notice. Country pages provide paginated access to the full register; true globe-scale clustering remains a separate milestone.

## Verified legal source
The only permitted initial import is the official US Department of Defense AARO case-resolution reports:
https://www.aaro.mil/Next-AARO-Home-redesign/Next-Parent/AARO-UAP-Case-DT/
Under 17 U.S.C. §105, official U.S. federal employee works are generally in the public domain:
https://www.copyright.gov/title17/92chap1.html
This does NOT waive third-party rights in embedded photos/videos. No third-party media is copied.
The manifest data/imports/aaro-reviewed.json contains 3 editorially approved, original paraphrases:
- US, Western United States (2021) — lights associated with commercial aircraft; no exact coordinates, no globe marker.
- IQ, Al Taqaddum (2017) — IR recording assessed as balloons; coordinate is air-base reference only.
- PR, Aguadilla (2013) — IR recording assessed as two sky lanterns; coordinate is airport reference only.
The status APPROVED means approved for public inclusion, NOT proof of unknown origin.

The schema now has two separate classification families: `review_status` controls public/editorial approval, while `assessment_status` (`resolved`, `unresolved`, `undetermined`, `disputed`) describes the assessment of the observed phenomenon by the cited authority. `assessment_confidence` (`high`, `moderate`, `low`, `not_stated`) and `assessment_authority` preserve what the original source actually concluded. All three initial AARO case reports are `assessment_status=resolved`; being in the registry is NOT synonymous with being unexplained. Visitors can filter by this assessment independently of editorial approval.

The rights-reviewed manifest has **3 unique records**, and the local SQLite test imports **3**. None have been confirmed imported into real Cloudflare D1 yet.

## Deployment commands (manual, after successful CI)
Authenticate Wrangler with the correct Cloudflare account first. Never commit tokens, UUIDs or passwords.

    npx wrangler d1 create aurora-uap-cases
    npx wrangler d1 execute aurora-uap-cases --remote --file=migrations/0001_init.sql
    node scripts/build-seed.mjs > /tmp/aurora-aaro-seed.sql
    npx wrangler d1 execute aurora-uap-cases --remote --file=/tmp/aurora-aaro-seed.sql
    npx wrangler d1 execute aurora-uap-cases --remote --command="SELECT COUNT(*) AS n FROM cases WHERE publication_status='published' AND review_status='approved' AND record_kind!='demo'"

The reviewed seed SQL generator validates source rights and uses idempotent inserts. Successful remote import is expected to produce 3 public cases. That is NOT a verified live count until the remote command returns it.

In Cloudflare Workers & Pages > aurora-uap > Settings > Bindings add a D1 binding with variable name **DB** attached to the real database, for production and optionally a separate preview DB. Redeploy to activate the binding. Confirm the real API and the /countries/DE route. Leave main on V1.3 until the database is ready.

## Weekly/monthly sync — prepared, NOT deployed
The independent Worker worker/scheduled.js has NO public HTTP handler. It reads ONLY the preapproved manifest from aurorauap.org. New records require human editorial review and merge first. Re-running does not duplicate sources/cases; it preserves manually withdrawn records.

To enable once the database is ready: copy wrangler.sync.example.toml to a private wrangler.sync.toml, replace the example D1 database UUID and deploy using:

    npx wrangler deploy --config wrangler.sync.toml

Cloudflare Crons: Mondays 03:00 UTC (sync); first of each month 03:00 UTC (integrity audit). Actual successful sync times are stored in import_runs and returned from D1. The Worker has not been deployed.
