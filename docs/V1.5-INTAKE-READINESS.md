# AURORA V1.5 — Secure text-only observation intake (DORMANT)

**This release does not activate public intake.** It implements a real quarantined Cloudflare D1 schema and a text-only API, disabled by default, plus a responsive local report-draft page.

## Implemented
- migrations/0002_intake_quarantine.sql: separate private intake_submissions and intake_review_events tables, immutable quarantined publication status, opaque idempotency key. No email, name, IP, home address, media or R2 fields. Free-text descriptions might still contain personal data, so protect all records as private.
- functions/_lib/intake.js: strict length, time-zone and date validation; unexpected contact/media properties rejected; optional GPS rounded to 0.1 degree. Report and audit are inserted atomically; duplicate submissions reuse the original receipt.
- GET /api/intake/status: safe status and public Turnstile site key only when all gates are ready.
- POST /api/intake/submit: exact same-origin HTTPS, JSON size limits, versioned consent, honeypot, server-side Cloudflare Turnstile Siteverify (including hostname and action). Accepted reports return HTTP 202, opaque ID and pending status; **never published**.
- reviewSubmission() is an internal domain function only. There is no public admin endpoint. Moderator decisions are audited; even approved records remain quarantined. Future Hermes integrations may recommend but never decide or publish.
- report.html: mobile-accessible local draft page with disabled submit unless the API advertises readiness. No file upload or contact collection.

## ALL release gates required

The production Cloudflare Pages environment must have:
1. Existing, migrated D1 binding DB (both migrations 0001 and 0002).
2. AURORA_REGISTRY_PUBLIC=enabled, with real D1 checks complete.
3. AURORA_INTAKE_ENABLED=enabled.
4. AURORA_INTAKE_LEGAL_APPROVED=yes ONLY after actual review and publication of privacy policy, controller details, contact process, lawful basis and retention/deletion rights.
5. AURORA_INTAKE_WAF_REVIEWED=yes ONLY after actual WAF rate limits and abuse alerts are tested.
6. AURORA_INTAKE_POLICY_VERSION=intake-v1-reviewed and AURORA_INTAKE_POLICY_URL=https://aurorauap.org/privacy. **This reviewed privacy page does not exist yet and must be published before enabling intake.** Never call draft privacy language a completed notice.
7. AURORA_INTAKE_HOSTNAME=aurorauap.org. This deliberately prevents activating the feature on preview domains.
8. AURORA_TURNSTILE_SITE_KEY and the separate secret AURORA_TURNSTILE_SECRET. Store the secret in Cloudflare secrets, NEVER in GitHub.

Do not set readiness flags merely to display an active button. These flags reflect independent operational and legal approvals.

## Applying schema 0002

Only after verifying actual D1 provisioned, migrated with 0001, backed up and scoped correctly:

    npx wrangler d1 execute DB --config <authorized-local-config> --remote --file=migrations/0002_intake_quarantine.sql

The existing manual AARO bootstrap action handles 0001 only. Do not assume 0002 is applied automatically.

## Moderation and safety

- Each report starts pending, publication_status=quarantined.
- Human moderator target: initial review within 72 hours, not a guaranteed response.
- Check spam, personal information, duplicates, aircraft, satellites, weather and astronomical possibilities.
- Human review approval does NOT equal publication. Real public release requires redaction and a separate approved publication workflow.
- No administrative API is exposed before verified Cloudflare Access authorization has been implemented.
- No R2 uploads, AI-auto-publication, contact data or public private-file URLs.

## Tests

    node --experimental-sqlite --test tests/intake.test.mjs
    node --experimental-sqlite --test tests/aurora-browser.test.mjs

SQLite integration checks real migration 0002, schema privacy, Turnstile rejection, disabled API, idempotency, human review, audit, and rollback on simulated failure. Browser tests exercise local drafts and a synthetic active state; this does not establish readiness to enable production.
